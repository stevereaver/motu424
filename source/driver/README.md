# MOTU PCI-424 ALSA Driver

A clean-room Linux ALSA kernel driver for the MOTU PCI-424 audio interface,
reverse-engineered from the original Windows driver binaries using QEMU VFIO
PCI passthrough tracing.

## Hardware

| Field        | Value                              |
|--------------|------------------------------------|
| Vendor ID    | `0x137a` (Mark of the Unicorn)    |
| Device ID    | `0x0004`                          |
| PCI Class    | `0401` (Multimedia audio controller) |
| BAR0         | 4 MB prefetchable memory — DSP program/data |
| BAR1         | 8 MB non-prefetchable memory — control registers |
| BAR2         | 16 bytes I/O port — FPGA configuration interface |

## Architecture

The driver is split into five source modules plus a shared header:

```
repo/source/driver/
├── motu424.h          Shared definitions: register map, data structures, MMIO helpers
├── motu424_main.c     PCI probe/remove, module entry/exit, ALSA card lifecycle, IRQ handler
├── motu424_fpga.c     FPGA bitstream loading via bit-banged serial on BAR1
├── motu424_init.c     Golden-sequence replay engine + DMA address translation + sync polling
├── motu424_dma.c      Coherent DMA buffer allocation + scatter-gather descriptor setup
├── motu424_pcm.c      ALSA PCM operations: open/close/prepare/trigger/pointer/ack
├── Makefile           Kernel module build system
├── convert_golden.py  Script to convert captured trace → binary init blob
├── init_sequence.bin  Compact binary init sequence (7192 register writes, 64 KB)
└── README.md          This file
```

## Initialization Flow

On `probe()`, the driver executes this sequence:

1. **PCI enable** — `pci_enable_device()`, `pci_set_master()`, set 32-bit DMA mask
2. **BAR mapping** — `pci_request_regions()` + `pci_iomap()` for BAR0/1/2
3. **FPGA load** — Bit-bang the Altera `.rbf` bitstream through BAR1 register `0x300008`
4. **Init sequence replay** — Write 7192 register values to BAR0 (DSP memory),
   with DMA physical-address translation to patch the Windows driver's hardcoded
   buffer addresses to our own
5. **Sync poll** — Poll BAR0 status registers until the card reports clock lock
6. **DMA alloc** — Allocate a coherent DMA buffer (up to 4 MB)
7. **IRQ request** — Register the interrupt handler
8. **PCM create** — Register ALSA PCM device with playback + capture substreams
9. **Card register** — `snd_card_register()`

## Audio Data Path

The MOTU PCI-424 uses a **multiplexed frame format**: each sample period, the
card transfers a fixed 392-byte frame containing 98 channels × 4 bytes. The
first two 32-bit words are status/magic words; audio data starts at word 2.

The driver bridges ALSA's stereo interleaved format to the multiplexed format:

- **Playback** (`ack` callback): Expand stereo ALSA data into the multiplexed
  frame, writing left/right at word offsets 2 and 3.
- **Capture** (`ack` callback): Extract stereo data from the multiplexed frame.
- **Pointer**: Read the hardware DMA position counter from BAR1, with a
  time-based fallback if the counter is not yet valid.

## Golden Sequence

The `init_sequence.bin` blob was generated by converting the QEMU VFIO trace
of the original Windows driver into a compact binary format. Each entry is
9 bytes:

```
[bar:1 byte] [offset:4 bytes LE] [value:4 bytes LE]
```

The trace was captured by running the official MOTU Windows driver inside a
QEMU/KVM VM with the PCI card passed through via VFIO, with QEMU tracing
enabled on the MOTU device's BAR regions. See `linux/instruct` and
`linux/motu_re_strategy.md` for the full capture methodology.

## Building

```bash
# On the target Linux machine with kernel headers installed:
cd repo/source/driver/
make

# Install the module:
sudo make install

# Install firmware:
sudo make install-fw
# (or manually copy init_sequence.bin and altera424b.rbf to /lib/firmware/motu424/)
```

## Loading

```bash
# Load the module
sudo modprobe snd_motu424

# Or insmod directly
sudo insmod snd_motu424.ko

# Check dmesg for initialization messages
dmesg | grep motu424

# The card should appear as an ALSA device:
aplay -l
arecord -l
```

## Firmware Files

Two firmware files are required in `/lib/firmware/motu424/`:

| File                | Description                          | Source                    |
|---------------------|--------------------------------------|---------------------------|
| `altera424b.rbf`    | Altera FPGA bitstream                | Extracted from `pci_424_fw.bin` |
| `init_sequence.bin` | Golden register-write init sequence   | Generated by `convert_golden.py` |

If firmware files are missing, the driver will attempt to proceed assuming a
warm boot (FPGA already loaded from a previous Windows session).

## Known Limitations

- The multiplexed frame format (98 channels) is hardcoded; only stereo
  playback/capture is exposed to ALSA. Multi-channel support requires
  exposing additional PCM devices or using the ALSA "multi" plugin.
- The hardware DMA position counter register offset may need adjustment
  based on further testing; a time-based fallback is provided.
- Sample rate changes require re-running the init sequence; currently
  only 48 kHz is tested.
- The driver does not implement mixer controls (volume, phantom power,
  clock source). These require mapping the Windows driver's IOCTL
  handlers to ALSA control elements.

## Reverse Engineering Methodology

The RE tools and data live under `repo/source/tools/` in the repository root:

- `repo/source/tools/golden/golden_sequence.c` — Raw QEMU trace converted to C write_reg calls
- `repo/source/tools/golden/golden_dsp.c` — DSP program upload sequence
- `repo/source/tools/golden/golden_fpga_bitbang.c` — FPGA bitbang sequence
- `repo/source/tools/replay/smart_replay.c` — Trace replay tool with DMA address translation
- `repo/source/tools/drivers/` — Prototype kernel drivers (motu_pci_alsa, motu_poke_driver)
- `repo/source/tools/poke/` — Userspace poke/test programs for hardware exploration
- `repo/source/tools/clock_sync/` — Clock synchronization and sync-finder tools
- `repo/source/tools/analysis/` — Python scripts for analyzing disassembly and traces
- `repo/source/tools/scripts/` — Shell scripts for VM setup and module reloading
- `linux/motu_re_strategy.md` — RE strategy document (in repo root)
- `linux/driver_development_strategy.md` — Driver development plan (in repo root)
- `linux/motu_hw_trace.log` — Raw QEMU VFIO trace (60 MB, in repo root)
- `ghidra_projects/` — Ghidra decompilation projects for the Windows binaries
